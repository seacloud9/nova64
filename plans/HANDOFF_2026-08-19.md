### Electron / WSL gotcha (important for running the GUI)
`pnpm install` under WSL fetches the **Linux** Electron binary; the smoke boot works via WSLg.
To run the real GUI on Windows, install/run `apps/desktop` from a **native Windows** shell so
the win32 binary is used. pnpm v10 blocks Electron's postinstall — `onlyBuiltDependencies:
[electron]` in `pnpm-workspace.yaml` allows it (run `pnpm --filter @nova64/desktop rebuild
electron` if the binary is missing).

## What #7 actually changed (for reviewers)

The vulnerability: `src/main.js` ran user cart code via `new Function` on any `EXECUTE_CODE`
`postMessage` **without validating sender or origin**. Any window/frame/extension able to
postMessage to the runtime could execute code.

- **`runtime/studio-protocol.js`** (new, pure ESM, no deps): `STUDIO_PROTOCOL_VERSION`,
  `StudioMessageType`, size limits (`MAX_CART_SOURCE_BYTES` 2MB, `MAX_LOG_MESSAGE_BYTES` 64KB),
  `byteLength`, `isTrustedOrigin` (never trusts `*`/`null`), `validateInboundCode`,
  `validateInboundStatus`, `acceptExecuteCode` (window-identity + origin + schema/size guard).
- **`src/main.js`**: `EXECUTE_CODE` handler now runs `acceptExecuteCode({expectedSource:
  window.parent, selfOrigin, allowedOrigins})` and drops the message on any failure before
  touching `new Function`. `EXECUTE_READY` now targets the embedder origin (`studioParentOrigin()`
  from `document.referrer`) instead of `'*'`. Trust anchor = **the message must come from
  `window.parent`** (the embedding Studio); dev cross-origin (Studio :3000 → runtime :5173) is
  allow-listed via the referrer origin.
- **`os9-shell/src/apps/GameStudio.tsx`**: receiver now trusts only `e.source ===
  iframeRef.current.contentWindow` on the expected Nova origin; bounds CART_LOG/ERROR payloads.
- **`tests/test-studio-protocol.js`** (new): 31 forged-message regression tests (pure node),
  wired into `pnpm test` and `pnpm test:quick`.
